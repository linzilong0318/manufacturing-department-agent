# 区间「增长/趋势」分析（2026-08 会话确立）

> 可复用判断方法论。当用户问"某区间内哪条线/哪个对象耗电增长最快、上升趋势最陡"等
> 区间趋势类问题时使用。设备计数见 device-inventory.md，产线耗电基准见 daily-energy-query.md。

## 核心：先澄清口径，再算斜率

「8/1~8/8 期间耗电增长最快」这类问法**天然有歧义**，不同定义答案不同，必须先澄清：

| 可能口径 | 含义 | 结果差异 |
|---|---|---|
| 期末 vs 期初 | 末值 - 初值（或环比） | 受停产日 8/8 骤降污染 |
| 工作日环比 | 最后工作日 vs 首个工作日 | 排除周末/停产日后看真实变化 |
| 线性趋势斜率 | 每日值最小二乘拟合的斜率 | 最反映"持续上升"，但受异常日主导 |

**处理：** 用 `clarify` 让用户选口径（多选），不要默认自选。本会话用户选「第三种：趋势斜率」。

## 斜率计算（最小二乘）

```
slope = Σ((x_i - x̄)(y_i - ȳ)) / Σ((x_i - x̄)²)   # x_i=0..N-1 天序, y_i=每日耗电
```

实现建议：MCP 拉 14 条产线逐日原始值（UNION ALL）+ execute_code/Python 本地算斜率，排序取最大。

## 两个必须排除的污染源（关键坑）

1. **停产/半生产日**：窗口末的停产日（如 8/8 全厂 60-86 kWh）会把所有线斜率拖成负值——先决定
   是否剔除停产日；要"真实生产增长"就只算生产日（8/1~8/7）。两口径都给并注明。
2. **计量异常跳变日**：某线单日巨值（如 M07 平日 0~86 突现 2103.7，属计量跳变）会让该线斜率
   虚高到 +132~+225，掩盖真实趋势。算斜率前先 scan 逐日值，标出异常日，剔除后重算，并加注
   "该线斜率系异常值主导，不可信"。

## 输出规范

- 给「含停产日」与「剔除停产日」两种斜率的结论（或注明采用哪种）；
- 明确标注异常线（如 M07）因跳变值斜率失真，真实趋势以剔除后为准；
- 若有线数据缺失（如 M09 电表断流）无法计算，如实说明，不强行填数。

## 关联

- 占比类问题（"各产线耗电占全厂比例"）：分子=各线区间 SUM，分母=全厂虚拟总表同区间 SUM
  （`quota_sub_{全厂总表}@public_dailyEnergyConsumption`），或 14 线 SUM 的 SQL 层合计；SQL 层算好再算百分比。
- 排名类（"当月从高到低/超 X 门槛"）：14 线 UNION ALL + GROUP BY SUM + ORDER BY，注意
  M09 等断流线会得 0，需标注为数据缺失而非真实 0。
